<h2 id="endfield">01 / 以《终末地》为参照：研究“质感”，而非只复制色阶</h2>
<p>在 2024 年 12 月的机核主创访谈中，团队将方向描述为强调质感的二次元写实风格，并讨论了角色与场景的协调、经过设计的黑白灰与色彩关系，以及随光照和视角变化的绘画笔触。它提供的是创作目标和表现线索，不能据此断言某一种笔触公式或材质模型就是游戏实装。<a class="cite" href="#ref-18">[18]</a></p>
<p><strong>我的研究判断是：</strong>如果以这个方向作为目标，核心问题就从“怎样把光照切成两段”扩展成“怎样在保持角色图形可读性的同时，让材质和空间关系可信”。增加真实感不等于把所有部分接入同一个写实模型；脸、头发、衣料与配件应分别决定保留什么、删掉什么。</p>

<h2 id="foundation">02 / 共同基础：卡通化的是光照信息的组织方式</h2>
<p>Cel Shading 常从明暗分层开始，但完整角色风格还依赖模型比例、法线、颜色、阴影形状、描边、动画与镜头。《Guilty Gear Xrd》的 GDC 2015 分享直接把定制着色器与为其制作的模型放在一起讨论，并强调对阈值、光向量、法线的艺术控制。这说明造型与着色应一起设计，而不是在任意模型上套一个 Ramp 就结束。<a class="cite" href="#ref-1">[1]</a></p>
<figure><img src="../assets/toon/pipeline.svg" width="1120" height="450" loading="lazy" alt="角色卡通渲染的五层结构：几何法线、明暗分层、材质响应、光照整合、采样输出"><figcaption>图 3｜本文建议的分析框架。五层共享规则，但可分别调试。</figcaption></figure>
<p>以一个方向光为例，可以先把连续的法线光照量映射成可控的亮暗区域：</p>
<pre><code>// 教学伪代码：仅说明单主光的明暗分层，不是完整着色器。
float s = dot(normalize(N), normalize(L)); // N、L 必须位于同一空间
float width = max(artistFeather, max(fwidth(s), 1e-4));
float litMask = smoothstep(threshold - width, threshold + width, s);
float3 bodyColor = lerp(shadowColor, litColor, litMask);
// 后续还需分别处理阴影可见性、光色、环境光、高光与输出转换。</code></pre>
<p><code>threshold</code>改变明暗覆盖，<code>artistFeather</code>控制设计上的软硬；<code>fwidth</code>提供局部像素尺度的过渡参考。它能缓解这一维阈值的部分锯齿，但不能保证解决阴影贴图、法线高频、轮廓或时间闪烁等所有问题。</p>

<p>Unity Toon Shader 将基础色、第一阴影色、第二阴影色及控制贴图分开组织，可作为参数设计的参考。颜色贴图与阈值、遮罩等数据贴图也应按各自语义设置色彩空间；不要把所有纹理统一当作 sRGB。<a class="cite" href="#ref-2">[2]</a></p>

<h2 id="skin">03 / 皮肤与脸：先保证形状可读，再决定保留多少真实感</h2>
<h3>皮肤并不等于“写实 SSS 加一道阈值”</h3>
<p>在日式动画语言内部，先确定目标更偏平涂动画、插画体积，还是强调材料质感的方向。以本文对《终末地》的审美偏好为例，应研究如何保留干净的脸，同时增加恰当的体积与环境联系；不能先把写实皮肤的全部高频信息搬进来。平涂方向可能更重视肤色、面部阴影形状和局部红润；偏写实方向才更需要细分粗糙度、法线与次表面散射。Epic 的 Subsurface、Subsurface Profile 等模型提供不同的散射表达，它们是实现选项，不是卡通皮肤必选项。<a class="cite" href="#ref-3">[3]</a></p>
<p>建议将脸部拆成三组控制：第一组决定大体积，例如额头、脸颊和下颌的明暗；第二组决定局部色彩，例如腮红、唇色与眼周；第三组决定材料提示，例如鼻尖或嘴唇的受控高光。不要让细小皮肤法线把整张脸的明暗边界切碎。</p>
<h3>法线控制与面部阴影控制图解决不同问题</h3>
<p>编辑着色法线会改变光照响应，但不会自动改变几何轮廓或阴影贴图中的遮挡。要消除鼻梁附近不理想的暗块，可以考虑专用法线、局部阈值或面部阴影控制图；具体选哪一种，应依据侧脸、俯仰和表情动画的表现判断。</p>
<p>常被称作“面部 SDF”的流程，可能使用真正的距离场，也可能使用随光向阈值变化的作者控制纹理。<strong>不要只看到名称就假定输入有统一数学含义。</strong>以下给出一种组织思路，而非某商业游戏的还原：先将主光转入头部局部坐标，再按左右光选择对应纹理或镜像，最后把方向参数映射为纹理阈值。纹理编码、比较正负与映射曲线必须在制作工具和着色器之间约定。</p>
<figure><img src="../assets/toon/face.svg" width="1120" height="420" loading="lazy" alt="头部局部坐标、面部阴影控制纹理和设计阴影合成的三步示意"><figcaption>图 4｜面部控制流程示意。这里的轮廓与纹理只是解释数据流，不是可直接使用的脸部 SDF。</figcaption></figure>
<p>头部骨骼变换、负缩放、左右手坐标和“光线传播方向／指向光源方向”的约定都可能导致反向。头顶光与背光还需要独立策略，不能默认仅靠一个水平角就能覆盖。设计阴影也不能替代真实遮挡：刘海、手臂和外部物体的投影是否进入脸部、以多大强度进入，需另定规则。</p>
<div class="takeaway"><strong>验收重点</strong>固定表情，让头部和主光分别旋转；检查正脸、侧脸、俯仰、背光，以及刘海投影。先验证光照在头部空间连续，再调颜色。</div>

<h2 id="hair">04 / 头发：区分发束体积、纤维方向和设计高光</h2>
<p>风格化头发首先需要清楚的发束体积。发束的亮暗分层可以与脸部共享主光方向，但高光通常需要专用控制。纤维散射模型与发束上的图形化亮带是两种不同表达，不应因为都叫“各向异性”就混用。</p>
<div class="table-scroll"><table><thead><tr><th>路线</th><th>主要输入</th><th>适合表达</th><th>需要接受的限制</th></tr></thead><tbody><tr><td>方向性高光近似</td><td>切线、光向、视向、粗糙度与遮罩</td><td>随光与视角变化的纤维方向感</td><td>切线不连续会造成高光断裂；简单模型不等于完整毛发散射</td></tr><tr><td>作者控制的亮带</td><td>发束 UV、控制纹理、偏移与形状参数</td><td>连贯、可设计的动画亮带</td><td>稳定性由映射与镜头测试决定，不自然等同于真实反射</td></tr><tr><td>MatCap</td><td>视空间方向映射、预渲染材质图与遮罩</td><td>快速形成统一的材质印象</td><td>与真实光源、遮挡不天然一致，镜头滚转需检查</td></tr></tbody></table></div>
<p>Unity Toon Shader 的 Angel Ring 明确是一种具有固定相机观察位置特征的发光泽控制，并有第二套 UV 等具体要求；它与任意“头发亮带”并不是同义词。MatCap 则利用预渲染球体图表达材料与光照，官方也提供相机滚转稳定等控制。<a class="cite" href="#ref-4">[4]</a><a class="cite" href="#ref-5">[5]</a></p>
<p>如果研究真实纤维响应，可从方向性高光近似进一步阅读 Disney 的毛发散射模型；该论文面向生产路径追踪，不能把完整模型的开销或适用性直接转移到手游发片。学习时应明确自己要保留哪一种视觉线索，而不是机械增加波瓣。<a class="cite" href="#ref-6">[6]</a></p>
<p><strong>调试顺序建议：</strong>先关掉高光检查发束体积；再显示切线方向；再只开一个高光分量；最后加入局部遮罩、颜色和次级亮带。发根到发梢的 UV 压缩、左右发束镜像和 LOD 切换，要与旋转镜头一起检查。</p>

<h2 id="eyes">05 / 眼睛：视线、层次与高光必须协调</h2>
<p>眼睛虽小，却是角色表情的视觉锚点。把全部信息画在一个平面上可以获得明确的风格，但侧视时可能缺少深度；加入角膜、虹膜与折射又会增加模型、UV 和着色之间的耦合。Unity HDRP 的 Eye Shader 将角膜折射、虹膜等作为眼部表达的一部分；Epic 也提醒 Eye 模型对几何和 UV 存在较强依赖。<a class="cite" href="#ref-7">[7]</a><a class="cite" href="#ref-3">[3]</a></p>
<figure><img src="../assets/toon/eye.svg" width="1120" height="440" loading="lazy" alt="卡通眼球角膜高光、虹膜、瞳孔与眼白的分层剖面示意"><figcaption>图 6｜眼球分层概念，不按解剖比例绘制。风格化实现可以删减层次，但需明确每层负责什么。</figcaption></figure>
<p>表面高光负责提示角膜曲面，虹膜负责颜色与深度，瞳孔负责视线焦点，眼白则需要与脸部处在同一光照关系中。作者绘制的固定高光与动态高光可以共存，但要约束亮度和数量，避免出现两个互相冲突的主光源。</p>
<p>低成本方案可使用单层不透明眼球、受控的虹膜 UV 偏移和高光贴图；这属于视差或反射近似，不应称为真实角膜折射。更完整的分层方案则要验证排序、边界遮挡、深度、透明开销，以及双眼在极端视角下的变化。</p>
<div class="takeaway"><strong>验收重点</strong>固定头部让眼球转动，再固定眼球让镜头转动。检查瞳孔是否漂移、虹膜是否滑出边界、眼睑遮挡是否正确，以及暗环境中的眼白是否过亮。</div>

<h2 id="costume">06 / 时装：保持同一风格，同时区分不同材料</h2>
<p>对本文追求的质感方向，时装是重点研究对象。同一套服装可以共享明暗色阶，但不能把布、皮革、金属全部压成同一个高光。材料区别应来自可识别的响应，而不是只换 Base Color。下面是本文建议的分析起点，不是固定生产参数：</p>
<div class="table-scroll"><table><thead><tr><th>材料</th><th>优先保留的线索</th><th>可研究的控制</th><th>常见误判</th></tr></thead><tbody><tr><td>棉布／粗织物</td><td>柔和体积、弱镜面、适量表面纤维感</td><td>粗糙度、织纹尺度、绒光</td><td>用强法线把布做成砂纸</td></tr><tr><td>缎面／丝质</td><td>随方向变化的长条高光</td><td>切线、各向异性、主次高光关系</td><td>把“更亮”当作“更像丝绸”</td></tr><tr><td>绒面</td><td>与观察和光照相关的柔软边缘响应</td><td>Sheen、纤维取向与覆盖</td><td>用无光照依赖的 Fresnel 加色代替所有纤维散射</td></tr><tr><td>皮革／涂层</td><td>表层反射、底层颜色与褶皱尺度</td><td>粗糙度分布、涂层与法线层级</td><td>所有褶皱都使用同样锐利的镜面</td></tr><tr><td>金属／饰件</td><td>反射色、环境结构与形状</td><td>粗糙度、环境反射、艺术高光</td><td>只提高 Metallic，却没有可读的反射环境</td></tr></tbody></table></div>
<p>Disney 的 Principled BRDF 提供了以少量直观参数组织材料响应的思路；Practical Volumetric Sheen 则针对表面纤维散射提出专门模型。二者可以帮助区分“通用材料控制”和“特定纤维现象”，但并不规定卡通服装必须完整采用它们。<a class="cite" href="#ref-8">[8]</a><a class="cite" href="#ref-9">[9]</a></p>
<p>织纹至少存在两种尺度：近景可以看见纱线结构，远景则更多表现为整体光泽、颜色和粗糙度。直接对高频纹理做阈值，可能把这些结构变成闪烁；一味模糊又可能丢失材料特征。研究时应把“平均颜色保持”和“高光分布保持”分开观察。</p>
<p>工程上可以共享材质功能模块，但不必追求一个吞下全部效果的巨型 Shader。独立的皮肤、头发和眼部路径，以及按需启用的服装特征，往往更容易说明数据依赖。是否拆分材质槽，还要结合绘制调用、状态切换和维护成本评估。</p>

<h2 id="iridescence">07 / 镭射、虹彩与薄膜：先问清楚是哪一种光学现象</h2>
<p>特殊材质应服从角色整体的面积、亮度与色彩层级，不是每个日式角色都需要虹彩、闪点或 POM。以下是可选的材料研究，不表示上述游戏全部采用。<br>“镭射”在美术沟通中常指彩色、随角度变化的表面，并非唯一的物理类别。选方案前，先看参考中的颜色如何跟随光源、视线和表面方向变化。</p>
<div class="table-scroll"><table><thead><tr><th>参考特征</th><th>候选机制</th><th>实现方向</th></tr></thead><tbody><tr><td>油膜、肥皂膜式的颜色变化</td><td>薄膜干涉</td><td>膜厚与折射率控制的光谱响应或经过验证的查表近似</td></tr><tr><td>光盘、光栅或微结构条纹的色散</td><td>衍射相关效应</td><td>考虑微结构方向、光向与视向的模型或有针对性的近似</td></tr><tr><td>主要要求设计感与配色变化</td><td>艺术化虹彩</td><td>视角／光角驱动的渐变、LUT、遮罩与高光组合</td></tr></tbody></table></div>
<p>Belcour 与 Barla 的研究将薄膜效应扩展到微表面框架，并处理光谱变化在 RGB 渲染中的积分问题。薄膜颜色不只是一个 <code>1 - N·V</code> 彩虹：它还与膜厚、界面介质以及光照几何有关。镜面微表面情形通常需要围绕参与反射的微表面方向评估；不能把宏观视角渐变当作等价物。<a class="cite" href="#ref-10">[10]</a></p>
<p>反过来，艺术化渐变是合理的成本与风格选择。只要命名清楚、测试条件明确，它可以比复杂光学模型更适合特定设计。衍射也有独立的波动光学研究，不应把一切彩虹表面都写成“薄膜干涉”。<a class="cite" href="#ref-11">[11]</a></p>
<figure><img src="../assets/toon/optics.svg" width="1120" height="430" loading="lazy" alt="薄膜干涉、离散闪点与视差遮挡的三种原理示意"><figcaption>图 7｜薄膜研究光的干涉，闪点研究离散反射事件，POM研究视线与高度场的交点。它们可叠加，但不是同一件事。</figcaption></figure>
<p><strong>测试建议：</strong>固定相机只转光，再固定光只转相机；分别观察颜色变化。遮掉大部分基础高光后再看虹彩分量，确认它究竟依赖什么，避免用大面积 Emissive 掩盖材料关系。</p>

<h2 id="glints">08 / 闪点与亮片：核心是离散反射与像素足迹</h2>
<p>闪点的可信度来自“少量微小反射体恰好将光反射向镜头”。固定噪声位置可以避免贴图无故游动，但仅有稳定噪声还不够：光向、视向、微片法线、大小与密度都会影响可见性。</p>
<p>Deliot 与 Belcour 的实时闪点研究，以像素覆盖区域中有多少微片满足反射条件为核心，并处理任意像素足迹的统计。这为近远距离的视觉连续性提供研究线索；论文中的速度比较有自己的测试条件，不应转写成某引擎或某手机的固定收益。<a class="cite" href="#ref-12">[12]</a></p>
<p>实用方案可以分成三档：少量、足够大的装饰亮片用显式几何或实例；亚像素闪点用带过滤和统计考虑的程序化或贴图模型；极远处逐步退化为整体镜面响应。切换时需要控制平均亮度与闪点密度，而不是把每一个远处亮点都粗暴放大。</p>
<p>要区分两种“闪”：一种是视角变化引起的正确闪烁，另一种是采样不足造成的时域不稳定。TAA 可能把前者抹平，也可能掩盖后者，不能作为唯一修复手段。高亮裁剪、曝光与 Bloom 还会改变闪点的尺寸印象。</p>
<div class="takeaway"><strong>验收重点</strong>同一表面慢速旋转、镜头缓慢拉远；对比抗锯齿开关与分辨率变化，记录亮点数量、平均亮度、拖影和稳定帧耗时。</div>

<h2 id="parallax">09 / 视差与 POM：用高度场增加深度，不等于增加几何</h2>
<p>法线贴图主要改变表面受光；视差映射则随视线调整纹理采样位置。POM 进一步沿切线空间视线搜索高度场，近似找到遮挡交点。PlayCanvas 的官方文档清楚区分了普通视差与 occlusion 模式，并列出采样数量等控制。<a class="cite" href="#ref-13">[13]</a></p>
<p>一种高度场约定下，局部偏移量可以概括为 <code>Δuv ∝ heightScale × Vts.xy / Vts.z</code>；但正负、参考平面和高度范围必须按坐标与纹理约定确定。接近掠射角时分母趋近零，需要淡出、截断或其他退化策略。这个比例关系不是可直接复制的完整 POM 实现。</p>
<ul><li><strong>采样一致：</strong>颜色、法线与其他表面数据需要使用一致的位移坐标，否则“深度”与“反光”会分离。</li><li><strong>导数与过滤：</strong>包含分歧的搜索循环中，隐式纹理导数可能不合适；可研究在循环前保存梯度并显式采样，但要按目标着色语言与平台验证。</li><li><strong>边界：</strong>基础高度场 POM 不改变网格外轮廓；UV 越界、镜像接缝和薄片侧面要单独处理。</li><li><strong>深度与阴影：</strong>虚拟交点、写入深度偏移、投影与自阴影是不同功能，不能因为 UV 已偏移就认为它们自动正确。</li></ul>
<p>在时装上，局部徽章、较厚织纹或凹槽可作为候选；对大面积、经常掠射观察的衣摆，实际几何有时更直接。POM 的开销随覆盖像素、步数、纹理访问和分歧变化，不能仅凭多边形减少就断言更快。远处回退普通法线是一个需要对比验证的选项。</p>

<h2 id="outline">10 / 描边与光照整合：让各部分看起来属于同一个角色</h2>
<p>反向外壳描边通过额外几何与剔除规则形成外轮廓；屏幕空间描边则可利用深度、法线或其他缓冲识别边缘。前者要处理硬边接缝、薄片与距离尺度，后者要处理深度缺失、内轮廓噪声和抗锯齿。它们都可以配合控制遮罩，不必对眼眶、睫毛、皮肤和衣服使用同一线宽。UTS 的入门文档就以眼部局部线宽控制举例。<a class="cite" href="#ref-14">[14]</a></p>
<p>多光源是另一个需要明确的风格决策：若每个灯都独立生成强烈的二值亮区，叠加后可能失去层级。可以设定主光负责体积，辅光只提供有限颜色或高光提示；也可以选择其他规则，但要让脸、头发、眼睛与服装共同遵守。</p>
<p>建议在明确的线性光照流程中组合分量，并单独控制艺术颜色的输入方式。曝光、色调映射和 Bloom 会影响最终色阶：过曝可能吃掉亮暗差异，过强泛光可能让布料像自发光。调试时保留一个固定曝光、关闭额外后期的基准视图。</p>

<h2 id="pipeline">11 / UE 与 Unity：先决定接入哪里，再比较功能</h2>
<p>同样的材质原理，落在不同渲染管线里，能得到的光源、阴影、深度和反射信息不同。不要把一段数学表达式与一个可交付的 Shader 系统画等号。</p>
<div class="table-scroll"><table><thead><tr><th>接入方式</th><th>优点</th><th>需要补齐的能力</th></tr></thead><tbody><tr><td>Unlit 中自定义颜色／光照</td><td>快速验证分层与艺术控制</td><td>不会自动拥有完整的场景光照、阴影与反射，需要明确传入或实现</td></tr><tr><td>现有材质／官方 Toon 框架扩展</td><td>能利用既有工具、特征和资源约定</td><td>核对版本、渲染路径、阴影及平台支持，不假定所有模型都能任意混合</td></tr><tr><td>自定义着色模型或渲染 Pass</td><td>可更深地参与光照与输出</td><td>引擎维护、G-buffer／前向路径、阴影和多平台一致性</td></tr><tr><td>后处理卡通化</td><td>便于快速建立整体风格试验</td><td>通常难以从最终画面完整恢复皮肤、头发和眼部各自需要的信息</td></tr></tbody></table></div>
<p>Epic 的着色模型文档适合核查已有 Hair、Cloth、Eye 等模型的输入与依赖；Unity 的 UTS 文档则适合研究卡通特征的组织。NiloCat 的公开 URP Toon 示例明确定位为教学样例，可作为理解自定义受光 Shader 的入口，而非未经验证就用于完整生产。<a class="cite" href="#ref-3">[3]</a><a class="cite" href="#ref-14">[14]</a><a class="cite" href="#ref-15">[15]</a></p>
<p>本文引用的文档包含特定版本和预览包。实际落地需以项目所用版本为准；不宣称这些接口在所有 UE、Unity 版本或手机渲染路径中都相同。</p>

<h2 id="performance">12 / 性能与稳定性：用一组可复现的画面来验收</h2>
<p>卡通渲染的简单色块不代表它天然便宜。额外描边、发片覆盖、眼部透明层、POM 搜索和高频闪点，仍可能成为瓶颈。移动 GPU 与 PC 的实际表现也不能从一个“指令数量”直接推导。</p>
<div class="table-scroll"><table><thead><tr><th>检查对象</th><th>观察方式</th><th>可尝试的退化策略</th></tr></thead><tbody><tr><td>脸部与头发明暗</td><td>主光和头部各转一圈；近、中、远景</td><td>降低远景细节，保留大体积和关键高光</td></tr><tr><td>头发与眼部覆盖</td><td>逐层关闭，观察 GPU Pass 与像素覆盖</td><td>减少透明叠层；对比不透明／裁剪方案的画质与代价</td></tr><tr><td>闪点与细织纹</td><td>慢速运动、分辨率与抗锯齿对比</td><td>按像素尺度过滤，逐步回归整体材料响应</td></tr><tr><td>POM 与特殊分量</td><td>固定镜头逐项关闭；检查掠射角</td><td>按距离、覆盖和质量档控制，保留明确的普通材质回退</td></tr><tr><td>描边与阴影</td><td>检查几何通道、分辨率与状态切换</td><td>减弱次要内部线条，按画面重要性安排质量</td></tr></tbody></table></div>
<p>Ben Golus 对网格着色器的研究展示了一个重要方法：同样“画出线条”，不同过滤方式在远处、斜视和细线合并时会产生不同结果。这类问题应以像素覆盖和信号频率分析，而不只是增加平滑节点。<a class="cite" href="#ref-16">[16]</a></p>
<p>建议每个实验保存设备、引擎版本、构建方式、分辨率、画质、抗锯齿、曝光、镜头和场景规模；比较 CPU／GPU 帧耗时、相关 Pass 与尖峰，同时保留画质对比。纹理大小、采样数、带宽、填充、分支和材质状态共同影响结果。没有真实测试前，不写“手游通用”“零成本”或固定毫秒收益。</p>

<h2 id="practice">13 / 从知识地图走向自己的作品</h2>
<p>以本文的审美方向作为目标，第一件作品可以是一个简化的日式角色半身材质研究：优先验证干净的脸、可读的发束和两三种服装材料；不必从完整游戏角色开始。如果目标是先补渲染能力，也可以缩小到一个头部或布片，完成“基线 → 单一现象 → 稳定性 → 成本”的闭环。第一轮只验证共同的明暗规则；第二轮只深入一种材料；第三轮再加入一项特殊效果。不要在同一轮同时承担模型、绑定、布料模拟、PCG和完整场景。</p>
<ol><li><strong>基础层：</strong>可解释地控制法线、主光和分层边界。</li><li><strong>材料层：</strong>选择织物、头发或眼睛中的一种，建立同条件比较。</li><li><strong>特殊层：</strong>从虹彩、闪点或POM选一项，说明采用物理模型还是艺术近似。</li><li><strong>交付层：</strong>一段视觉展示、一组调试对比、一份实现局限与性能记录。</li></ol>
<blockquote>专业程度体现在：能说明画面中的现象、选择了哪一种近似，以及这个选择在什么条件下仍然成立。</blockquote>
<p>本文是研究入口。后续具体作品应补上自己的代码、输入资产、版本条件和实测数据，让综述逐步连接到可复现的实验。</p>
