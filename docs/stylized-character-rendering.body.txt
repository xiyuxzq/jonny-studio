<p>脸是这些里面最容易做错、也最影响观感的一项，所以文章中段花最多篇幅在它上面。想看更多卡通渲染的细节技巧，MIZI 在知乎的系列是个好入口，面部篇里还整理了赛马娘的面部阴影算法<a class="cite" href="#ref-8">[8]</a>。</p>

<h2 id="pipeline">01 / 一个角色是怎么拆开着色的</h2>
<p>一个角色通常按部位分成脸、头发、眼睛、身体、衣服几套材质，各自的 Shader 共享同一组输入：角色光方向、头部骨骼朝向、相机方向。分区信息不靠 Shader 里写死，而是烘在贴图和顶点色里，这样美术可以直接改。</p>
<figure><img src="../assets/toon/pipeline.svg?v=20261018-sdf" width="1120" height="420" loading="lazy" alt="角色着色的五个组成部分：材质分区、漫反射、高光、描边、特殊处理"><figcaption>图 2｜角色着色的组成。示意图，不对应任何一款游戏的实际管线。</figcaption></figure>
<p>原神系的角色会带一张 ILM（光照图），每个通道存一类信息。通道含义每个游戏都不一样，下面是两份公开实现里的写法，对照着看就明白为什么说“别照搬通道约定”：</p>

<p>Gaolingx 的 README 里 B 通道的说明有乱码，我只能确认它与高光强度有关。顶点色同样各家不同：他的实现里 <code>VertexColor.a</code> 是描边粗细，<code>VertexColor.g</code> 是 Ramp 偏移。</p>
<p>雪羽在知乎上的原神还原对 G 通道的用法更能说明问题：沿用《罪恶装备》的 LightMap 思路，阴影分两级，一级阴影随光照变化，二级阴影固定不变，所以不能只用一次半兰伯特切完。她还提到崩坏3 的原始算法很绕，自己改成了更直接的写法，认为没有必要那么复杂<a class="cite" href="#ref-29">[29]</a>。</p>

<h2 id="diffuse">02 / 漫反射：阈值加 Ramp</h2>
<p>最基础的一步是把连续的 <code>N·L</code> 切成亮暗两块，边界留一点可调的过渡，再让暗部的颜色从 Ramp 贴图里取，而不是单纯压黑。</p>
<pre><code>float hl   = dot(N, L) * 0.5 + 0.5;                       // 半兰伯特
float lit  = smoothstep(_ShadowRange, _ShadowRange + _ShadowSmooth, hl * aoMask);
float2 uv  = float2(lit, rampRow);                        // 横轴明暗，纵轴是 ILM.a 选出的材质行
float3 shade = SAMPLE_TEXTURE2D(_Ramp, sampler_Ramp, uv).rgb;   // Ramp 的 Wrap Mode 必须是 Clamp
float3 diffuse = albedo * shade;                          // 亮部落在 Ramp 最右端，值为白</code></pre>
<p>几个细节来自两份实现：Ramp 的 Wrap Mode 要设成 Clamp，否则边缘会采到另一端的颜色，出现噪点<a class="cite" href="#ref-4">[4]</a>；原神的 Ramp 把明暗交界放在偏右的位置，亮部那一大段几乎没有变化，直接去掉，省带宽也给美术留了空间；Ramp 分白天和夜晚两组行，用一个开关切换<a class="cite" href="#ref-13">[13]</a>。暗部泛红、泛冷这类“假次表面散射”就是直接画在 Ramp 里的。</p>
<p>色彩空间要分开处理：Ramp 和基础色是 sRGB，ILM、阈值图、各种遮罩是线性数据，导入时关掉 sRGB，否则 Gamma 会把数值扭曲<a class="cite" href="#ref-7">[7]</a>。</p>
<div class="interactive-figure" aria-label="明暗分层教学演示"><div class="interactive-title"><span>INTERACTIVE / 明暗分层</span><span>同一球面 · 同一光向</span></div><canvas id="toon-ramp" width="900" height="330" role="img" aria-label="连续漫反射、硬阈值与带过渡分层的球面示意"></canvas><div class="ramp-control"><label for="toon-light">光源角度 <output id="toon-angle">35°</output></label><input id="toon-light" type="range" min="-85" max="85" step="1" value="35"></div><p>CPU 生成的理想球面，只有一盏方向光，没有投影和环境光。三个球用同一组数据：左边是连续的 <code>N·L</code>，中间是硬阈值，右边是带过渡的阈值。</p><noscript>开启 JavaScript 后可调节光源角度。</noscript></div>
<p>这套思路的源头可以追到《罪恶装备 Xrd》。它的美术风格分享里讲到：模型的法线是手工调过的，让明暗边界落在画师想要的位置；光向量也可以按镜头和角色单独调；再用阈值贴图和顶点色在局部推移阴影边界；描边除了背面外扩，还有画在贴图上的“本村线”。Qian Kanglai 照着公开资料在 Unity 里复现过一版，结论是整体就是 Blinn-Phong 加 Toon，参数全由贴图驱动<a class="cite" href="#ref-1">[1]</a><a class="cite" href="#ref-2">[2]</a>。后来的原神系做法是同一个思路的工业化：把手工调的东西固化成 ILM、Ramp 和顶点色。ashyukiha 在知乎配套的开源 URP 实现，把面部阴影图、Ramp、金属高光和描边都放在一起，适合对着代码读<a class="cite" href="#ref-23">[23]</a>。</p>
<p>但脸不能用这套办法。</p>

<h2 id="face">03 / 脸：SDF 阈值图</h2>
<h3>为什么 N·L 做不了脸</h3>
<p>人脸的法线起伏太大。鼻梁、眼窝、下颌线处的法线变化剧烈，用 <code>N·L</code> 加阈值切出来，边界是破碎的：鼻子在脸颊上投出一块奇怪的黑，下颌线锯齿状，侧光时眼眶整个被吞掉<a class="cite" href="#ref-7">[7]</a>。动画里的脸不是这样的，它的阴影是几块干净的形状，光转动时整体平滑地推过去。</p>
<p>MIZI 的面部篇把常见方案分成三类：修改法线、距离场阴影、Matcap<a class="cite" href="#ref-8">[8]</a>。Yu-ki016 的说法更简短：目前卡通脸部光照主要是修改法线和使用 SDF 贴图两条路，新出的二游基本都用 SDF<a class="cite" href="#ref-9">[9]</a>。</p>
<p>改法线有三种做法，问题也都类似：</p>
<ul>
<li><strong>球形包裹体法线。</strong>把一个球的法线传递到脸上，阴影形状就是球的阴影。操作简单，但只能得到球的形状。</li>
<li><strong>改拓扑再改法线。</strong>《罪恶装备》和《蓝色协议》的做法：把脸的布线改成目标阴影的形状，再逐点调法线。能得到理想的形状，但很费工，而且两种阴影形态之间会跳变。罪恶装备视角固定可以忽略，蓝色协议里就能明显看出来。</li>
<li><strong>拉平法线或画法线贴图。</strong>修改后的法线不连续，同样有跳变<a class="cite" href="#ref-8">[8]</a>。</li>
</ul>
<p>Matcap 在光源不动时可以直接用来切分光影，七つの大罪的技术分享就这么做，理由是动画里的阴影更看重情绪表达而非物理正确<a class="cite" href="#ref-8">[8]</a>。光一动它就用不了。</p>
<p>SDF 路线正好相反：形状完全由画出来的图决定，不同形态之间自然过渡。MIZI 提到这个方法最早用在脸上的出处不明，疑似来自米哈游的技术分享，原神里确实在用<a class="cite" href="#ref-8">[8]</a>。张洋铭整理的流程是：美术画关键帧，经过 SDF 插值输出阴影贴图<a class="cite" href="#ref-12">[12]</a>。</p>
<h3>阈值图里存的是什么</h3>
<p>这张图的每个像素存一个数 <code>T</code>，含义是：<strong>光从正前方转到多少度时，这个点进入阴影，除以 180°</strong>。运行时只要算出当前光的角度 <code>φ</code>，拿 <code>T</code> 去比：<code>T &gt; φ/π</code> 就是亮，否则是暗。光从 0° 转到 180°，每个像素在恰好的那一刻变暗，整体看来就是阴影形状在脸上平滑推过。</p>
<p>这样做的好处是把“逐像素算光照”变成了“整个头部共用一个角度”。mos9527 的说法很直接：着色只和光照角度有关，相当于对一块法线一致的平面打光<a class="cite" href="#ref-5">[5]</a>。</p>
<p>有一个常被混淆的名字问题。真正的 SDF（有符号距离场）只出现在<strong>烘焙阶段</strong>，用来把几张关键帧插值成中间形状；运行时用的这张图，CandleSpark 称之为“SDF 过渡图”，它的灰度是一组等高线，每条等高线对应一个光照角度下的明暗分界。他特别提醒：初学者别把过渡图当成严格的 SDF 去理解，两者不是一回事<a class="cite" href="#ref-3">[3]</a>。网上说“脸部 SDF 贴图”指的几乎都是这张过渡图。</p>
<figure class="wide-figure"><img src="../assets/toon/face.svg?v=20261018-sdf" width="1120" height="440" loading="lazy" alt="面部阈值图的三个步骤：关键帧二值图、烘焙出的阈值图、运行时与光照角度比较"><figcaption>图 3｜面部阈值图从制作到使用。左：画几张不同角度的二值阴影图；中：烘焙成一张灰度图（灰度即进入阴影的角度）；右：运行时只比较大小。头部和阴影形状由程序合成，仅作示意。</figcaption></figure>

<h3>怎么烘焙</h3>
<p>流程是固定的：</p>
<ol>
<li>手绘或在 Blender 里用平行光渲染，得到若干个角度下的二值阴影图，比如每 15° 一张。程序渲染出来的会带上不好看的几何阴影（鼻影），要手工修。</li>
<li>对每张二值图求 SDF：亮区内取正、暗区内取负，边界处为零。</li>
<li>相邻两张图之间对 SDF 值做线性插值（算法出处见<a class="cite" href="#ref-10">[10]</a>），找出每个像素“由亮变暗”的那个角度，这个角度就是 <code>T</code>。</li>
<li>把所有区间的结果合成一张图。CandleSpark 的做法是先对每对关键帧做过渡图，再逐像素取平均合成<a class="cite" href="#ref-3">[3]</a>；下面的写法更直接，一次扫完所有关键帧。</li>
</ol>
<pre><code>import numpy as np
from scipy.ndimage import distance_transform_edt as edt

def signed(lit):                      # lit: bool，True = 受光
    return edt(lit) - edt(~lit)       # 亮区为正，暗区为负，边界处过零

def bake(masks, angles):
    """masks: 各关键帧二值图，亮区随角度增大而缩小；angles: 对应角度（度，升序）。
    返回 T：该像素进入阴影时的光照角度 / 180。"""
    S = np.stack([signed(m) for m in masks]).astype(np.float64)
    a = np.asarray(angles, np.float64)
    T = np.full(S.shape[1:], np.nan)
    T[S[0] &lt;= 0] = a[0] / 2                        # 第一帧就已在阴影里
    T[S[-1] &gt; 0] = (a[-1] + 180) / 2               # 最后一帧仍然受光
    for k in range(len(a) - 1):
        s0, s1 = S[k], S[k + 1]
        hit = (s0 &gt; 0) &amp; (s1 &lt;= 0)                 # 亮暗在 k 与 k+1 之间翻转
        ang = a[k] + s0 / (s0 - s1 + 1e-12) * (a[k + 1] - a[k])
        T[hit] = ang[hit]
    return T / 180</code></pre>
<p>我用合成的椭球头做过验证（亮区边界已知），每 15° 一张关键帧，烘出来的 <code>T</code> 与解析解的平均误差约 0.7°，最大 7° 出现在贴近脸颊边缘处。真正做脸时，误差主要来自关键帧画得不够单调，而不是算法。</p>
<p>几个制作上的要点，来自几篇文章的共同经验：</p>
<ul>
<li><strong>每个像素必须单调变化。</strong>亮区要随角度只缩不涨，否则某像素在 30° 亮、60° 暗、90° 又亮，就没法用一个阈值表示。EmiteInna 把这点说得最清楚<a class="cite" href="#ref-6">[6]</a>。</li>
<li><strong>0° 和 180° 两张关键帧必须有。</strong>缺了全亮或全暗那张，会在正面光时鼻尖留一块三角阴影，光稍微偏一点，阴影就从鼻子一侧跳到另一侧；背光时同理出现亮斑。CandleSpark 提到原神和星穹铁道也有这个现象，游戏里很少正脸对光所以不明显，绝区零干脆取消了鼻尖三角<a class="cite" href="#ref-3">[3]</a>。</li>
<li><strong>形状本身要人来设计。</strong>鼻子不该向脸颊投影，下颌线要画成向上弯的弧线而不是几何给出的直线，眼眶要比周围略亮<a class="cite" href="#ref-7">[7]</a>。</li>
<li><strong>SDF 不必是精确的欧氏距离。</strong>只要过渡平滑、单调即可。EmiteInna 用曼哈顿距离的广度优先搜索、甚至图像软件里的模糊做过实验，效果可以接受<a class="cite" href="#ref-6">[6]</a>。需要线性时间的精确算法，常用的是 8SSEDT：不知道像素在阴影内还是外，就扫两遍，先假设在内、再假设在外，两遍结果相减就是有符号距离<a class="cite" href="#ref-12">[12]</a><a class="cite" href="#ref-10">[10]</a>。GPU 上可以用 Saito 算法，把关键帧累加成台阶图，再用对应图的 SDF 求到上一级台阶和下一级台阶的距离<a class="cite" href="#ref-11">[11]</a>。</li>
<li><strong>分辨率至少 512，建议 1024；关掉 sRGB；别压缩。</strong>Gamma 会把阈值扭曲<a class="cite" href="#ref-7">[7]</a>，压缩会破坏边缘上的数值<a class="cite" href="#ref-8">[8]</a>。</li>
</ul>

<h3>运行时怎么用</h3>
<p>需要三个向量：头部的前向、右向、上向，必须来自头部骨骼，不能用模型自身的固定轴。头骨在动画里会转，用固定轴的话脸一低头阴影就错位。mos9527 的方案是直接从骨骼取，Morgana 的 URP 复现用一个脚本把头骨的方向通过 MaterialPropertyBlock 传进 Shader<a class="cite" href="#ref-5">[5]</a><a class="cite" href="#ref-20">[20]</a>。</p>
<pre><code>// L：指向光源的单位向量，世界空间；fwd/right/up：头部骨骼的方向
float FaceShadow(float2 uv, float3 L, float3 fwd, float3 right, float3 up, float feather)
{
    // 去掉上下分量，只看水平面内的光向。光正好在头顶时长度趋近零，要给个回退
    float3 Lh = L - up * dot(L, up);
    Lh = normalize(Lh + 1e-5 * fwd);

    float FL = dot(fwd, Lh);                       // cos φ，φ 为光与正前方的夹角
    float RL = dot(right, Lh);                     // 正负决定光在左边还是右边

    // 图只画了一侧：光在另一侧时水平翻转 UV。翻转方向取决于你的贴图画的是哪一侧
    float2 suv = float2(RL &gt;= 0 ? uv.x : 1 - uv.x, uv.y);   // 注意写 &gt;= 而不是 &gt;，避免 sign(0)=0
    float T = SAMPLE_TEXTURE2D(_FaceSDF, sampler_FaceSDF, suv).r;

    float thr = 0.5 - 0.5 * FL;                    // 阈值映射，必须与烘焙时一致
    float w   = feather * min(thr, 1.0 - thr);     // 过渡带随阈值向两端收窄，feather 取 0.2 到 0.5
    return w > 1e-4 ? smoothstep(thr - w, thr + w, T) : step(thr, T);
}</code></pre>
<p>其中有几处是实现时才会撞上的：</p>
<ul>
<li><strong>阈值映射有两种常见写法，必须和烘焙对上。</strong>一种是 <code>thr = 0.5 - 0.5·cosφ</code>（半兰伯特形式，被很多教程采用，CandleSpark 的节点图也是这个），另一种是 <code>thr = φ/π</code>（线性于角度，本文的 Python 代码和演示用的是这个）。两种都要求 <code>f(0)=0</code>、<code>f(π/2)=0.5</code>、<code>f(π)=1</code>且单调，函数形状只影响阴影推进的节奏<a class="cite" href="#ref-3">[3]</a>。</li>
<li><strong>垂直方向的光被丢掉了。</strong>投影到水平面意味着光源上下移动，脸部阴影纹丝不动，这是故意的：光源高度一变，几何阴影就会出现不好看的形状，丢掉它画面反而整齐<a class="cite" href="#ref-3">[3]</a>。如果项目确实需要处理垂直光，知乎上有 360° 的 SDF 方案，但制作成本高很多<a class="cite" href="#ref-9">[9]</a>。</li>
<li><strong>过渡带要随阈值收窄。</strong>软边宽度不能是常数。阈值接近 0 或 1 时（正面光和背光），固定宽度的过渡带会越过灰度范围，光一偏阴影就整块跳变。CandleSpark 建议宽度向两端收窄，且本身别超过 0.05，否则阴影位置会明显偏移<a class="cite" href="#ref-3">[3]</a>。秋大叔的终末地复刻用的是同一个思路：<code>smoothstep(max(0, 2f-1), min(1, 2f), sdf)</code>，其中 <code>f</code> 是 0 到 1 的阈值。这个窗口以 <code>f</code> 为中心，半宽恰好是 <code>min(f, 1-f)</code>，也就是上面代码里 <code>feather = 1</code> 的情形<a class="cite" href="#ref-28">[28]</a>。</li>
<li><strong>左右翻转要求脸模对称。</strong>脸模不对称，就得画左右两张图，或者接受一点不匹配<a class="cite" href="#ref-5">[5]</a>。</li>
<li><strong>LiKira 的星穹铁道版本</strong>另外用图的 G 通道做了眼部阴影遮罩，把眼睛区域强制抬亮，防止脸在阴影里眼睛也跟着变黑<a class="cite" href="#ref-4">[4]</a>。</li>
</ul>

<h3>脸上还要补的几处</h3>
<p>阈值图只解决了“阴影形状”。秋大叔复刻终末地的脸时，在它上面补了这些东西，大多数 SDF 脸都会遇到<a class="cite" href="#ref-28">[28]</a>：</p>
<ul>
<li><strong>背光补偿。</strong>角色背对光、正对镜头时，按阈值算脸会整个变黑。他把一个补偿量加到光与前向的余弦上：<code>backLight = saturate(-dot(camFwd.xz, L.xz)) * saturate(-FL)</code>，补偿量取 <code>0.5 - 0.5·FL²</code>，再把 <code>FL + backLight × 补偿</code> 送进阈值映射。身体的漫反射里用的是同一套背光补偿，这样脸和身体不会脱节。</li>
<li><strong>脸和脖子的衔接。</strong>脖子是另一套 Shader，光照分布和脸不同，交界处会出现一条缝。做法是用一张区域遮罩，脸取 SDF 算出的明暗，靠近脖子的部分渐变为模型法线的 <code>N·L</code>。作者说即使这样处理，仍然留有一点缝。</li>
<li><strong>SSS 和边缘光的范围。</strong>脸的模型比较特殊，直接用 <code>1 - N·V</code> 得不到日式风格，要用贴图限制范围。边缘光则从 SDF 图的另一个通道重新还原一个假法线来算。</li>
<li><strong>两个通道存 SDF。</strong>他拆到的图把 x、y 两个通道平均后当阈值用，z 通道用来还原假法线。他的猜测是为了优化，但自己也说不确定。</li>
<li><strong>鼻尖与嘴唇高光。</strong>如风的拆帧里，嘴唇高光是单独一张图，鼻尖高光放在下巴 AO 图的 A 通道；脸的最终明暗是 SDF 结果乘 AO<a class="cite" href="#ref-22">[22]</a>。鼻尖高光也可以用同样的 SDF 方法做：光在正侧方时最亮，所以阈值要变成侧光为 0、正面和背光为 1，即 <code>abs(dot(Lh, fwd) * 0.5 + 0.5 - 0.5) * 2</code>，另一侧用 UV 遮罩屏蔽<a class="cite" href="#ref-8">[8]</a>。</li>
</ul>

<h3>SDF 阈值图的局限和补救</h3>
<ul>
<li><strong>没有垂直方向的变化。</strong>前面说过这是故意的，但如果项目要处理，Yu-ki016 做过 360° 的方案：画好各个光照方向的二值图（他画了 9×7+2 共 65 张，花了一周空闲时间），各自转成 SDF，拼成图集，运行时按光源的两个角度算 UV，采样四次插值。这个方案成立有一个条件：后一张的亮区必须覆盖前一张，也就是单调性。很多工具把 255 个插值结果累加进一张图来省空间，累加会破坏插值信息，水平轴方案里无伤大雅，全角度方案里就会出错<a class="cite" href="#ref-9">[9]</a>。</li>
<li><strong>软阴影和变形区域。</strong>MIZI 指出纯 SDF 的两个问题：过渡会有色阶感；曲率不同或 UV 拉伸的地方，软硬交接会不一致<a class="cite" href="#ref-8">[8]</a>。阴影边界落在眼睛、嘴这类会变形的区域时，纯 SDF 还会随表情被拉伸。赛马娘的做法（Cygames Tech Conference）是用类似 SDF 的方式只画特征区域，再和修正后的法线光照混合，这样变形区域的边界不会被拉伸。分享里没讲具体算法，MIZI 给了一版自己的还原<a class="cite" href="#ref-8">[8]</a>。</li>
<li><strong>脸型本身。</strong>卡通角色在较低 FOV 下好看，第三人称常用的高 FOV 会让面部轮廓变形。很多模型的正脸会做扁，一部分原因就是抵消这个变形<a class="cite" href="#ref-8">[8]</a>。</li>
</ul>

<h2 id="bangs">04 / 刘海投影与脸部的其余问题</h2>
<p>阈值图只负责脸自己的明暗。头发投到脸上的影子是另一件事。动画里常见和发型形状相似的脸上阴影，但真实的阴影贴图在很多角度下投出来很难看，所以通常先把头发对脸的投影去掉，再用 trick 补一个好看的<a class="cite" href="#ref-17">[17]</a>。常见做法有两种：</p>
<ul>
<li><strong>屏幕空间偏移。</strong>早期做法是给头发或脸写模板，在屏幕空间偏移后做模板测试。延迟渲染下更简单：做脸的着色时，把屏幕空间深度偏移一小段，和头发深度比较，头发更近就判为被遮挡<a class="cite" href="#ref-17">[17]</a>。</li>
<li><strong>投影网格。</strong>把刘海网格复制一份，沿光向偏移后画一遍，只写到脸上。Morgana 的复现里有一个专门的 <code>BangsShadowSimple</code> 就是这样做的<a class="cite" href="#ref-20">[20]</a>。秋大叔复刻终末地时，截帧里直接拿到一个已经错位好的刘海模型，用模板渲染即可；他让阴影强度随“日光直射强度”变化，主光不直射时就去掉<a class="cite" href="#ref-28">[28]</a>。如风的拆帧也提到前额阴影有偏移，前刘海似乎是半透明处理<a class="cite" href="#ref-22">[22]</a>。</li>
</ul>
<div class="takeaway"><strong>踩坑</strong>投影的偏移距离要随相机距离缩放，否则镜头一拉远，刘海影子就变得比脸还大。偏移方向用的光向要和脸部阈值图用同一个角色光，不然两处的阴影方向会打架。</div>

<h2 id="hair">05 / 头发</h2>
<p>头发要先解决形体，再做高光。</p>
<h3>先把法线压平</h3>
<p>发片网格的法线通常是乱的，直接拿来算明暗会碎成一堆小块。常见做法是把法线朝一个球面拉：取头部中心作球心，用位置减球心得到球面法线，再按遮罩混合。Morgana 的复现里叫“法向压平，模拟圆柱”，球心由脚本从骨骼取，混合量由 ORM 贴图的 R 通道控制<a class="cite" href="#ref-20">[20]</a>。</p>
<pre><code>float3 sphereN = normalize(positionWS - _HeadCenterWS);
float3 hairN   = normalize(lerp(N, sphereN, _Flatten * mask));</code></pre>
<h3>高光：切线加噪声偏移</h3>
<p>头发上那条亮带（俗称天使环）是许多根发丝高光叠出来的。用一张面片代替发丝时，普通法线高光是个点，叠不出环。Kajiya-Kay 的做法是用发丝方向（切线）代替法线来算高光：发丝近似圆柱，法线在圆周上没有唯一值，但切线是确定的。强度由切线和半角向量夹角的正弦决定，再用指数收窄<a class="cite" href="#ref-15">[15]</a>。</p>
<pre><code>float3 ShiftTangent(float3 T, float3 N, float shift) { return normalize(T + N * shift); }

float StrandSpec(float3 T, float3 V, float3 L, float exponent)
{
    float3 H    = normalize(L + V);
    float  TdotH = dot(T, H);
    float  sinTH = sqrt(saturate(1.0 - TdotH * TdotH));
    float  atten = smoothstep(-1.0, 0.0, TdotH);         // 压掉背向的那一半
    return atten * pow(sinTH, exponent);
}

float n    = tex2D(_ShiftTex, uv * _ShiftTiling).r - 0.5;          // 噪声让亮带边缘参差
float wide = StrandSpec(ShiftTangent(T, hairN, _Shift1 + n * _Strength), V, L, _Exp1);   // 宽、软
float thin = StrandSpec(ShiftTangent(T, hairN, _Shift2 + n * _Strength), V, L, _Exp2);   // 窄、亮
float band = smoothstep(_Cut - _Soft, _Cut + _Soft, wide + thin);                      // 卡通化</code></pre>
<p>三点说明。第一，原文的 <code>shift</code> 偏移沿法线方向推切线，作用是把亮带整体上下移动；噪声图是再叠一层扰动，让亮带不那么圆润<a class="cite" href="#ref-15">[15]</a>。第二，切线必须沿发丝方向，所以头发 UV 的排布很关键：V 方向要沿发根到发梢。有 MMD 复现终末地渲染的作者提到，所用二游模型的 UV 很好，各向异性高光因此能发挥出来，高低频两层高光叠加的效果很出众<a class="cite" href="#ref-19">[19]</a>。第三，两层叠加的写法就是上面的 <code>wide</code> 和 <code>thin</code>：偏移和指数不同，一层宽软，一层窄亮。</p>
<p>Morgana 的复现里还有一个细节：高光不是直接出白色，而是用一张 LUT 上色，横轴是角度、纵轴是位置，所以亮带从发根到发梢可以有颜色变化<a class="cite" href="#ref-20">[20]</a>。</p>
<h3>终末地的头发高光为什么在任何角度都好看</h3>
<p>Tiansing 在游戏里观察到，服装和头发的高光方向只跟随相机，类似摄影里的补光灯，让角色在光照不丰富时也有清晰的轮廓<a class="cite" href="#ref-24">[24]</a>。秋大叔复刻时给出了一种具体写法：造一盏从相机打向角色的虚拟灯，按“日光直射强度”和真正的主光混合，再用混合后的灯算半角向量<a class="cite" href="#ref-28">[28]</a>。</p>
<pre><code>// camFwd 取 UNITY_MATRIX_V[2].xyz，指向相机身后，也就是“朝向相机的方向”
float  fy       = lerp(0.5, L.y, _DayStrength);
float3 fwdLight = normalize(float3(camFwd.x, fy, camFwd.z));
float3 Lnew     = L * _DayStrength + 2.0 * fwdLight;                   // 直射强度为 0 时只剩相机灯
float3 Hnew     = normalize(V * (2.0 + _DayStrength) + Lnew);
float  NoH      = dot(N, Hnew);                                         // 后面照常走 GGX</code></pre>
<p>他对比了用与不用的 <code>N·H</code> 分布：用了之后，高光不再有明显的斜上方光源感。头发的做法也在同一篇里<a class="cite" href="#ref-28">[28]</a>：</p>
<ul>
<li>高光用的平滑法线存在法线贴图的 z、w 通道，漫反射仍用模型法线。</li>
<li>为了做出游戏里整齐平行的高光，他把法线中与相机右向重合的分量去掉，让法线只在前和上两个方向变化：<code>n = normalize(n - dot(n, camRight) * camRight)</code>。他自己称这是“下策”，因为调光源一直做不出游戏里的整齐效果。</li>
<li>给视线的 y 分量加一个偏移，可以整体上下移动高光位置。</li>
<li>高光用一张美术准备的颜色贴图着色，再叠第二次 Kajiya-Kay 算一圈光晕。</li>
</ul>
<p>这些是复刻者按截帧反推的，不是官方实现。MMD 复现终末地渲染的作者也提到各向异性高光配合高低频两层叠加效果很好<a class="cite" href="#ref-19">[19]</a>。</p>
<figure><a href="https://endfield.hypergryph.com/#information" target="_blank" rel="noopener noreferrer"><img src="https://web.hycdn.cn/upload/image/20260714/e4c3c1219db9fe092bbb6a8df8bc265a.png" width="1920" height="1080" loading="lazy" referrerpolicy="no-referrer" alt="终末地官方干员叙事诀：履旧尘宣传封面中的头发、眼睛与脸部近景"></a><figcaption>图 4｜官方「诀：履旧尘」宣传封面。头发大块的明暗很稳定，亮带集中在发束上半部。单帧只能看结果，不能判断它是随光还是随相机。来源：<a href="https://endfield.hypergryph.com/#information" target="_blank" rel="noopener noreferrer">《明日方舟：终末地》官网影像资料</a>；© HYPERGRYPH。</figcaption></figure>

<h2 id="eyes">06 / 眼睛</h2>
<p>卡通眼睛的高光一般直接画在贴图上，不跟着光走，因为眼神光是角色表情的一部分。Morgana 的复现里，眼睛做了两件事：角膜法线球面化，加一个 MatCap 高光，另外有一些颜色处理<a class="cite" href="#ref-20">[20]</a>。结构上不需要真的做角膜折射，这是性价比问题。</p>
<p>真正麻烦的是<strong>让眼睛透过刘海显示</strong>。日式动画里眼睛永远不会被头发挡住，3D 里要靠渲染顺序和模板缓冲做到。常见做法是这样的顺序：</p>
<ol>
<li>先画脸、身体、眼睛等不透明部分。</li>
<li>再画头发，头发的 Pass 里写模板值：<code>Stencil { Ref 1 Comp Always Pass Replace }</code>。只有通过深度测试的头发像素才会写入 1，被脸挡住的后脑头发不会写。</li>
<li>最后画一个眼睛的叠加 Pass：<code>ZTest Always</code>，<code>Stencil { Ref 1 Comp Equal }</code>，半透明混合。这样眼睛只在被头发盖住的像素上显示出来。</li>
</ol>
<p>日式卡通渲染基础技术和 Project Sekai 三周年的图形更新里都讲过这类做法，后者列了两种：一种是眼睛 <code>ZTest Always</code> 再用头发做遮罩，另一种是先写眼睛的模板值、画头发时再按模板判断<a class="cite" href="#ref-16">[16]</a>。我上面写的是第一种的模板版本，细节需要自己对着项目的渲染队列调。</p>
<div class="takeaway"><strong>踩坑</strong>叠加 Pass 用了 <code>ZTest Always</code>，所以闭眼时必须同步关掉，否则眼睛会透过眼睑和头发显示出来。头发和脸之外的前景物体（比如手）要在头发之前画，才不会被眼睛盖住。</div>

<h2 id="outline">07 / 描边</h2>
<p>背面外扩的原理：同一个网格再画一遍，剔除正面（<code>Cull Front</code>），顶点沿法线向外推，输出描边色。深度测试保证只有推出轮廓之外的部分可见，看起来就是一圈线。基础版有一串问题，silence394 的文章把它们依次解决了，下面是处理顺序<a class="cite" href="#ref-14">[14]</a>（LiKira 的描边代码则主要来自 NiloCat 的教学示例<a class="cite" href="#ref-26">[26]</a>）：</p>
<ol>
<li><strong>近大远小。</strong>在模型空间外扩，距离固定，拉远后线变得断断续续，拉近又太粗。改在裁剪空间推，并乘 <code>posCS.w</code> 抵消透视除法，线宽在屏幕上就固定了。</li>
<li><strong>非均匀缩放。</strong>带缩放的矩阵作用在法线上会让它不再垂直于表面，描边在某些位置消失。法线要用逆转置矩阵变换，Unity 的 <code>TransformObjectToWorldNormal</code> 已经处理了这点。</li>
<li><strong>横竖线宽不一致。</strong>NDC 空间被屏幕宽高比拉伸，横向要乘 <code>height/width</code> 修正。</li>
<li><strong>远处线还是太粗。</strong>屏幕等宽的代价是物体缩小后线宽不变，按距离做衰减。</li>
<li><strong>硬边处断裂。</strong>立方体 6 个面 24 个顶点，同一位置的顶点法线各不相同，外扩后各走各的，棱角处裂开。要用平滑法线：离线把同位置顶点的法线求平均，存起来用。</li>
</ol>
<pre><code>Varyings OutlineVert(Attributes v)
{
    // 平滑法线存在切线空间里（比如压进 UV2/UV3），这里还原到模型空间。
    // 存切线空间是为了蒙皮动画：存模型空间的话，骨骼一转法线就对不上了。
    float3 bitangent = cross(v.normalOS, v.tangentOS.xyz) * v.tangentOS.w;
    float3 smoothOS  = v.smoothTS.x * v.tangentOS.xyz + v.smoothTS.y * bitangent + v.smoothTS.z * v.normalOS;

    float4 posCS = TransformObjectToHClip(v.positionOS.xyz);
    float3 nWS   = TransformObjectToWorldNormal(smoothOS);
    float2 dirCS = normalize(mul((float3x3)UNITY_MATRIX_VP, nWS).xy);
    dirCS.x *= _ScreenParams.y / _ScreenParams.x;                    // 宽高比修正

    float fade  = 1.0 - smoothstep(_FadeStart, _FadeEnd, posCS.w);   // posCS.w 即视空间深度
    float width = _OutlineWidth * v.color.a * fade;                   // 顶点色 A 控制局部粗细
    posCS.xy += dirCS * width * posCS.w;                              // 乘 w 抵消透视
    ...
}</code></pre>
<p>原文里有两个地方和代码对不上，照抄会踩：正文说描边 Pass 要关闭深度写入，示例却写 <code>ZWrite On</code>；平滑法线虽然算出来了，后面的法线变换依然用的是原法线，要改成 <code>smoothNormal</code> 才生效<a class="cite" href="#ref-14">[14]</a>。</p>
<p>外扩描边画不好的地方，可以把线画在贴图上。网易游戏学堂的总结把这类方法分成三种：直接画在贴图上（锯齿最大，只适合很小的地方）；本村线（《罪恶装备 Xrd》的做法：贴图上画一条与水平、垂直轴对齐的黑线，给需要描边的位置多建一个位置相同的顶点，把它的 UV 埋进黑线里，调整两者的 UV 关系让三角形被黑线覆盖，这样粗细可控也不出斜向锯齿，代价是对 UV 要求高）；以及用 SDF 还原内描边，理论上也不会有锯齿，但作者没找到商业案例<a class="cite" href="#ref-30">[30]</a>。</p>
<p>脸部的描边通常还要做深度偏移，让眉毛、睫毛附近的线不被脸吃掉。LiKira 在描边顶点着色里用一张遮罩贴图控制 Z 偏移，脸部再额外加一点固定偏移<a class="cite" href="#ref-4">[4]</a>。至于终末地的描边，我没有找到可靠资料。Tiansing 只提到过场里有撞色边缘光，头发是深度边缘光，衣服是单边菲涅尔<a class="cite" href="#ref-24">[24]</a>；秋大叔复刻的描边用平滑法线外扩，并按相机距离和屏幕空间修正宽度<a class="cite" href="#ref-28">[28]</a>；Morgana 的复现也是带深度缩放的背面外扩<a class="cite" href="#ref-20">[20]</a>。</p>

<h2 id="light">08 / 光照：角色光和场景光分开</h2>
<p>上面所有部分都依赖“主光方向”。如果直接用场景里的太阳，脸会在镜头转动或角色走动时出现阴阳脸、鼻影乱跳。Tiansing 对终末地的观察是<strong>分离式光照</strong>：角色光照从场景光源中独立出来，局内把光照方向摆正到相机方向，过场里再自定义；场景光经过衰减后只负责整体明暗和色彩晕染<a class="cite" href="#ref-24">[24]</a>。他特别提到，游戏里大部分时候脸上看不到明显的半影，只有大招、特写这类镜头里才有 SDF 半影，推测游戏里有两类灯，一类让脸产生半影，另一类只改亮度和颜色。这和 SDF 脸是配套的：阈值图只在光的水平角度上有意义，光向一旦被锁在相机附近，脸就永远处于画好的那几个形状里，不会出现怪角度。他自己的评价是角色像是“屏蔽了所有难看的角度，只保留了镜头下最美好的样子”。他也说明了这篇文章是不看截帧、纯凭观察的猜测，“不保真”<a class="cite" href="#ref-24">[24]</a>。</p>
<pre><code>// 相机空间里的一盏固定灯：右上、偏向相机一侧（Unity 的相机看向 -Z，所以 +Z 在相机身后）
float3 rigVS = normalize(float3(0.35, 0.55, 0.75));
float3 rigWS = mul((float3x3)UNITY_MATRIX_I_V, rigVS);

// 与场景光混合；混合量为 1 时完全由相机决定
float3 L = normalize(lerp(sceneLightDirWS, rigWS, _CamLightBlend));
float3 lightColor = sceneLightColor;                    // 色温和强度仍然来自场景</code></pre>
<p>混合量不必取满。取 1 时角色会像贴在相机上的纸片，丢掉环境感；取 0.6 到 0.8 之间，既能保住脸的稳定，又保留了一点场景方向。这个数需要在你的镜头体系里调。</p>
<h3>日光直射强度：同一个角色的两种着色状态</h3>
<p>秋大叔复刻时注意到，终末地的主光强度会随天气和位置变化，角色整体会变暗，但如果只是降低主光强度，光照方向的分布不变，角色站在墙角时仍然有强烈的主光方向感，而现实里这时角色应该主要被周围的次级光照亮。他的做法是引入一个 0 到 1 的“日光直射强度”，把着色分成两个状态<a class="cite" href="#ref-28">[28]</a>：</p>
<ul>
<li>强度为 1：完整的主光逻辑，三层色阶（亮部、暗部、暗中暗）、主光边缘光、刘海阴影、主光参与的高光。</li>
<li>强度为 0：去掉依赖主光直射的东西，漫反射改成明暗两层，<code>N·L</code> 减弱，高光完全由相机灯决定，刘海阴影消失。</li>
</ul>
<p>这是复刻者对游戏表现的解读，没有官方说明。思路值得借鉴：把“主光能不能直射到角色”作为一个单独的参数，而不是靠调光源强度。</p>
<p>边缘光常见的实现是深度偏移法：把视空间位置沿法线 XY 方向偏移一小段，用偏移后的屏幕坐标采样深度图，如果那处深度比当前像素深出一个阈值，就判为边缘，再乘菲涅尔遮罩和基础色。需要开启深度纹理，Shader 里要有 DepthOnly Pass<a class="cite" href="#ref-4">[4]</a>。</p>

<h2 id="body">09 / 衣服、皮肤和后处理</h2>
<p>终末地和原神系最大的区别在衣服。原神系的衣服基本是 Ramp 加 ILM 的卡通漫反射，高光用遮罩画出来。Tiansing 的观察是：衣服混合 PBR，间接光用带颜色的 IBL，比预制 Matcap 补充了更丰富的间接光；大量皮衣这类工业风材质混 PBR 也不违和，同时脸部弱化半影，避免“二次元脸加写实衣服”的木偶感<a class="cite" href="#ref-24">[24]</a>。如风的拆帧也说皮肤用 Ramp，衣服是改过的 PBR<a class="cite" href="#ref-22">[22]</a>。</p>
<p>Morgana 的 URP 复现可以当作这条路线的一个参照：</p>
<ul>
<li>漫反射用 Sigmoid 阶跃，边界硬度可调；亮部、暗部、“暗中暗”三层由 Ramp 染色；逆光时 Ramp 的 UV 自动偏移，提亮暗部；加一点顶光补光，防止下巴死黑。</li>
<li>高光走 GGX，间接光用拟合的 IBL；材质用 ORM 贴图（R 金属度、G 反射率、B AO、A 光滑度）。</li>
<li>皮肤单独一套 Shader：暗部从皮肤 LUT 里取色，加 SSS 透光和粗糙度控制。</li>
<li>后处理是三样：32³ 的 3D LUT 调色、Bloom、FXAA<a class="cite" href="#ref-20">[20]</a>。</li>
</ul>
<p>这是一个社区作者的复现，不是游戏的实际管线。拿来用的话，只看它怎么把 PBR 和 Ramp 放进同一套流程就够了。</p>

<h2 id="practice">11 / 自己做一遍的顺序</h2>
<ol>
<li><strong>球加 Ramp。</strong>先用一个球把阈值、过渡、Ramp 取色跑通，转光看明暗。</li>
<li><strong>头：阈值图加头骨。</strong>找一张或画一张阈值图，接到头骨方向，光转一圈，头转一圈。重点看正面光和背光两端有没有跳变。需要现成工具的话，破晓写过 Unity 下的 GPU 版 UDF 和面部 SDF 烘焙工具<a class="cite" href="#ref-11">[11]</a>。</li>
<li><strong>刘海投影。</strong>用深度偏移或投影网格，乘到脸的阴影上。</li>
<li><strong>头发。</strong>先压平法线，出大块明暗；再做 Kajiya-Kay 单层，调通后叠第二层。</li>
<li><strong>描边。</strong>先做基础外扩，再依次加屏幕等宽、宽高比、距离衰减、平滑法线。</li>
<li><strong>角色光。</strong>把前面所有用到光向的地方切到同一个角色光，再试镜头旋转。</li>
<li><strong>最后才是衣服的 PBR 和后处理。</strong></li>
</ol>
<p>每一步的检查方式一样：光绕角色转一圈，头转一圈，镜头推拉各一次。</p>
